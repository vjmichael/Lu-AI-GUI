## Design decision

The historical Windows AF_UNIX prototype had unresolved ACL/reparse and peer-identity gates. This candidate uses Windows kernel named pipes instead of restoring the old file-based endpoint. Linux retains AF_UNIX and SO_PEERCRED. Both adapters use the same v1 exchange/v2 diagnostic compatibility and canonical bounded HMAC request/response implementation, random 16-byte invitation ID and 32-byte secret, nonce, two-minute expiry, one-use snapshot, 4096-byte frames and three-second whole-frame I/O deadline. No change to five-count projection, receiver/sender native consent, archive storage, or model/tool authorization. No cross-machine exchange. User-visible UI is unchanged; Windows availability is enabled only when explicitly compiled with `windows_dx_eval` (non-release evaluation). Default Windows builds remain disabled.

Windows uses a random fixed local pipe name, one first-instance-only server handle, remote-client rejection, non-inheritable handles, explicit protected DACL containing only the current process user SID, and readback from both endpoint handles rejecting unexpected owner, ACL entries, inheritance, or rights. The receiver uses identification-only SQOS; the sender queries the actual last-read client's kernel token and reverts before authenticating and responding. Same-account applications holding a valid invitation are trusted, as on Linux; not a defense against a compromised account, administrator/kernel adversary or a leaked invitation. No impersonation-based operations on third-party data. Stop retires the handle and joins the worker; bytes already delivered cannot be recalled. Abrupt process death releases the handle without a persistent filesystem endpoint. No broadening of remote authority.
