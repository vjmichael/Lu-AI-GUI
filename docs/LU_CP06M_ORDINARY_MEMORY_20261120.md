# CP-06M — ordinary conversation memory integration

Base: published `f3805ba9e8fd986c6c8e68519ab14abc129b5341`.
This is a local Debian development candidate, not a release or a change to the active hosted acceptance branch.

## Scope and implementation

The existing native chat store, ANSF journals, goal/clarification projector, verified procedure/belief readers, operational memory and continuity store remain authoritative. No new database, renderer tool registry, or independent memory service. Ordinary Send already reconstructs these original memory inputs, but had separate lexical and semantic retrieval paths with three gaps: same-chat history outside the recent context window was excluded; semantic lookup could rank superseded revisions; and identical earlier questions could displace the source containing the answer. The authenticated recall function now binds the exact latest host-authenticated human turn before reading current-revision source data, includes earlier same-chat messages before that original entry, and excludes identical user prompts before lexical ranking/limit. Other conversations remain confined to the same installed profile. Original immutable revisions can still be explicitly requested by source ID and are labeled potentially superseded, not current facts. Truncated excerpts and omitted matches are explicit. A failed local embedding read retains lexical matches; semantic ranking and pending indexing exclude old revisions. The original explicit history-search API remains available.

Ordinary Send and the existing non-exact workspace route use the same authentic memory context adapter. Exact resume, belief and procedure requests bypass speculative live-read negotiation and generic recall, preserving their existing source/custody/clarification gates. Goal context includes its original revision identity, incomplete-window markers and explicit non-authorization. Bounded recall/goal context is attached without replacing the original saved text. Historical claims, even source-linked claims, do not establish fresh facts, current OS custody, completion or permission. No auto-retry or fresh effects are possible through recall. No engineering controls added to user-facing Chat. A plain-language decline of earlier-conversation search suppresses that retrieval path only, not the separate same-chat typed history or saved goal. This is not a global memory-off mode.

## Qualification boundaries

Native source and model fixtures exercise original SQLite reopen, stale/foreign/substituted turn refusal, repeated prior question exclusion, current versus superseded revision recall, lexical fallback, historical intent routing, goal deferral and the original procedure/continuity/regression suites. A genuine local GGUF fixture exercises the same history, recall, supervisor and assistant journal path with fixed synthetic messages, not the installed graphical Send button. Source fidelity is distinct from the model giving the right answer. The initial model attempt with 192 output tokens failed to complete the expected answer and surfaced a repeated-question ranking issue; the repeat uses the ordinary 512-token allowance and retains the same answer criterion. Preserve actual terminal results separately. Real embedding-quality comparison, large-history coverage, full UI/installed/physical matrix, and CP-09M comparative benchmark remain separate gates. No public-network dependency and no changes to the hosted security or web qualification workflows.
