## Contract and scope

- Complete explicit bounded request grammar: copy one regular file within its selected folder to a new name, or move/rename it to a new name within that same folder. A named original file must match the trusted picker exactly; ASCII leaf-only grammar for named requests, no arbitrary destination path, compound action, or inferred target. Native host chooses a fresh destination name. More general legacy routes retain their existing policy, not qualified by this work.
- Model proposes only selection copy_file, move_file, or null. No callable grant, resource handle, destination argument or approval originates in the model. Original persisted human turn, active foreground ticket, revocation watermark, original request and raw model response digests bind the proposal and audit. Exact native review includes source, new target, size, content digest and computed Protobuf input digest. Separate trusted human approval of that review is necessary before the existing capability and policy engines admit the single native effect. Application adapter uses native chooser and separate confirmation, with one-use review queue and existing Wave2 recovery intent, not a WebView approval flag. Recheck original task, cancellation, source and no-clobber conditions; refuse prior effect ID or substituted audit. No automatic retry on uncertain outcome.
- Existing registered native copy/move Protobuf contracts and durable dispatcher retained. Independently decode and reconcile APPLIED durable receipt with native output, actual destination bytes/SHA-256 and source preservation (copy) or absence (move). Record FILE_TRANSFER_DIRECT_V1 with verified/conflict verdict tied to the actual receipt. No success from unverified outcome; no repeated effect on receipt or presentation failure. Grounded feedback identifies original task, exact review, receipt and checked observation digests. The result is an observation at verification time, not an everlasting filesystem guarantee.
- Genuine second model response selects verified_completion or unverified after checked native feedback. Host renders receipt-supported facts, including actual filenames, size and original-file state. Invalid/failed continuation can give explicitly attributed verified-receipt fallback only if the original task remains live; no fabricated model FINAL_ANSWER. Post-effect Stop retains durable effect evidence but suppresses completion. A human refusal can complete the chat with an explicit no-change message; it is never a completed effect. Native dialog warns that an effect already in progress is not necessarily reversible by Stop.
