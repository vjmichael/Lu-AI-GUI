# CP-11B-R3 — Session-bound changing text files

Scope: a local Linux regular `.txt` file selected by the operator, one approved line, up to 2 KiB and 32 lines; the selected line is at most 160 UTF-8 bytes. The scheduled model can request literal `READ` once per claimed occurrence. A host-owned read-only file handle is kept in memory; the model never supplies paths. In-place edits are admissible, but file replacement, symlinks, hard links, missing/invalid data and unsupported filesystems are rejected. Device/inode/birth identity and bounded repeated stable reads bind the observed snapshot. A hash of the actual observation and the independently extracted line are retained per occurrence; a matching model answer is required for completion. The receipt is not a signature or independent attestation of arbitrary facts in the file.

File permission does not persist through process restart. The schedule and reports do; active file schedules pause and require a fresh native selection/approval of the same file, followed by an explicit resume. An unsafe/unavailable read pauses a recurring schedule for review. Revocation atomically terminates the schedule and stops a claimed occurrence while retaining completed reports; the retained read handle is dropped. Fixed-note and text-only schedules retain the earlier semantics. Model loading, generic tools, directory scans, remote files, write authority and Windows live-file support are outside this scope. No hard real-time filesystem guarantee; no hostile-profile authentication claim. Prioritization remains the existing bounded idle-only admission.
