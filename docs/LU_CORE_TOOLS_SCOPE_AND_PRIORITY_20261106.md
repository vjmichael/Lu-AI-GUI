## 1. Why this change is being made

Lu Core is not intended to replace every specialist desktop application. It is the first-party, AI-friendly environment through which an assistant discovers information, chooses tools, acts with explicit authority, schedules work, manages hardware resources and preserves task continuity. **A usable, dependable task path matters more than maximally deep feature lists.** Every native domain should have a bounded job; specialist operations may remain in specialist programs.

This is a NEW explicit owner decision and thus takes precedence where it conflicts with earlier speculative tool-expansion plans. The preserved original Jan-Mod tool design remains the primary architectural source except where superseded by the owner's explicit direction. See [merged native tool design](LU_NATIVE_TOOLS_MERGED_DESIGN.md) and [central design](LU_CENTRAL_DESIGN.md). Existing completed source and historical PR/CI notes are factual history, not authorization to resume old expansion. These priorities **do not mean the ranked areas have passed tests**.

## 3. Critical interfaces and reuse — avoid duplicate implementations

### 3.1 Reader, OCR, vision and indexing

One high-level Reader asks what the file is, catalogs its sections, and retrieves only the requested content. A text layer or EPUB chapter is parsed natively when reliable; offline OCR is requested for scanned text; an explicitly supported vision backend is used *selectively* for diagrams, forms and complex visual arrangements. Return typed page/chapter/paragraph/source anchors, text confidence or an explicit unknown, original/derived digests and a distinction between verified extraction, unverified OCR and model inference. Indexes are rebuilt/incrementally refreshed when immutable source identity changes. A large book is a stream and an index, not a giant model prompt or whole-RAM materialization. One user-facing action; internal engines remain testable and separately replaceable.

### 3.2 Filesystem intelligence and source identity

Model receives compact file reference candidates rather than a large raw directory dump. Native index respects scoped roots, symlink/reparse and case-insensitive identities, renames/moves/deletes, ACL and consent changes; always rechecks permission and source freshness before opening/editing. Path search, metadata search, content search and optional semantic retrieval are distinct cost classes. Do not silently index the entire machine or send local content to a network service.

### 3.3 Jobs, Guardian, models and transfers

Background task journal is the source of truth for scheduling/terminal state; guardian owns admission and resource budgets; workers own actual tool execution. Transfer Manager handles verified downloads/uploads (with independent authority); model library and Browser are clients, not duplicate download engines. An AI Operations Layer selects known capabilities and models, prepares just the necessary context, and requests work, but cannot override admission, memory/VRAM ceilings or user permissions. Treat model search, package acquisition, local model load, inference and cleanup as distinct recoverable phases.

### 3.4 Research, Observe and specialist boundaries

Research owns evidence/citations and publishing style; Reader owns source extraction; Browser owns approved online observation; Observe owns opt-in application events and privacy; they exchange *typed evidence*, not untrusted natural-language grants. Lu Core image editor and Office/Git keep modest general-purpose operations; advanced creative and developer tasks remain in specialist apps / Lu IDE / future DLCs.
