# CP-11B — durable scheduled reminders (bounded first delivery)

This work extends the existing native BackgroundScheduler SQLite database, desktop watchdog and Tasks tab. It is an inert **reminder** lane, not a second worker scheduler or a persistent executable grant. Existing supervised background file scans retain their separate original admission, resource accounting and restart-reapproval policies. No Cognitum capability is duplicated.

Supported: direct Tasks form, explicit original Chat requests such as `Remind me in 10 minutes to review my notes` or `Remind me every day to review my notes`; no model required. The host independently parses fixed relative duration grammar, validates one minute to one week, observes the original chat, and shows exact plain-language native consent. No permission derives from an AI message, attachment, recalled content, guessed date or stale original request. The form also requires explicit native approval. Relative timing begins only after approval.

Inert text only. One-shot and repeated intervals persist, with UTC epoch timestamps displayed in the local timezone. A day is 24 elapsed hours, not a wall-clock calendar or DST-aware rule. When Lu is closed, no external process executes; overdue occurrences are coalesced into a durable unread count on next opening. Due publication and advancing the cadence use the same SQLite transaction. No automatic model load, arbitrary tool, network request, file read, new system service, or external delivery. The host watchdog triggers these local notices independently of resource-intensive workers; task pages are event-refreshed and periodically query native durable state. Owner checks, bounded inputs, maximum 128 active and paused rows, maximum 4096 total retained reminders, stale-notice acknowledgement fencing, pause/resume and permanent cancellation. Paused periods are not backfilled. Terminal history remains readable in the app; no cleanup/export UI in this slice.

Native lifecycle qualification should distinguish deterministic clock-boundary tests from actual installed GUI runs with natural elapsed time. A missed reminder is a notice of when the reminder was due, not proof of background application execution. General scheduled model-based work and tool effects remain separate CP-11B acceptance requirements: typed original-human proposal, durable occurrence identity, appropriate fresh consent/authority, original worker/resource custody, revocation, recovery and independently verified outputs. No scheduled model or generic command permission has been added.
