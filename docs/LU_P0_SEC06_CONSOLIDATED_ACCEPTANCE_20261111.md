## Purpose and strict evidence rule

An adversarial source assertion, SQLite simulation, compiler success,
positive return code, or completed model answer is not independent OS
custody evidence. A specific original worker / cgroup / Windows Job, source
head, original effect journal and owner-visible restart state must agree.
The test program never restores tool permission or retries effects.

Native receipts generated by `scripts/p0-sec06-consolidated.mjs` preserve
the test machine OS, exact HEAD, SHA-256 of the source inventory, individual
test names, result codes and SHA-256 hashes of each saved log. These local
hashes detect accidental or post-run evidence modification; they are **not**
remote signatures, trusted-machine attestations or proof against a same-user
attacker who can replace both the receipt and the logs. Independent review
and owner physical acceptance remain mandatory.
