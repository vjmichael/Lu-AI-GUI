# Lu Core P06 — OBSERVE-PRIVACY-01 (Observe & Learn)

## P06 nonce-bound foreground OS identity receipt

The native WGC SHA-256 receipt now uses different domains for the verified foreground HWND and the unidentifiable generic GraphicsCapturePicker item. In foreground mode, HWND, owning PID, process creation FILETIME, task nonce and fully blanked frame geometry are hashed together. The OS identifiers never appear in stdout, the GUI or model context. Invalid foreground identity refuses a receipt. Generic selection uses a separate **unverified** domain, never borrows foreground source identity. Rust tests verify that changing HWND/PID/birth changes the result but changing original pixel values does not. This is stronger provenance for foreground mode only, not general source attribution, independent GUI verification or working visual model access.

## P06 native Windows NSIS install/uninstall evidence harness (not yet executed)

Added `scripts/verify-observe-nsis-cycle-windows.ps1` to run **the actual hash-reviewed NSIS install/uninstall lifecycle** on an explicitly confirmed clean disposable Windows machine. It rejects a pre-existing Lu install/process, requires independent SHA-256 for installer, installed Lu and WGC worker and reviewed uninstaller basename, selects a fresh temporary target path, runs standard NSIS `/S` and `/D`, checks the real installed binary hashes and optional separate native UIA smoke, runs the actual uninstaller and verifies app/worker removal plus uninstall-registry cleanup. It records failure stage and preserves forensic evidence instead of automatically deleting an unknown install directory. This is code and release-test procedure, **not a physical Windows PASS**. Running on an existing everyday Lu installation is explicitly forbidden. It does not certify WGC source identity, privacy-redacted pixels, model GUI capability or GPU quota.

## P06 future reviewed-region sanitization and independent evidence hardening

- **Zero-default image compositor (source only):** New `approved_regions_only_bgra` copies pixels exclusively inside a bounded list of individually reviewed regions into a newly allocated, fully zeroed BGRA image. Missing/invalid/overflowing regions refuse to produce *any* output buffer; D3D row padding and all outside pixels stay zero. Existing region-mask algorithm still available. This is intentionally **not connected** to WGC receipt, UI preview or model media; no trusted user-reviewed region grant or source/coordinate attestation exists yet.
- **GUI verifier:** The existing typed expected-vs-running independent comparator now refuses an extra observation/check ID outside the approved intended test plan rather than ignoring it. Rust tests and focused native Windows/Linux CI now cover this.
- **GPU resource observation (physical harness option):** `verify-observe-installed-windows.ps1 -SampleGpuMemory` requires the manual worker lifecycle trial; when a real OS worker is seen, the harness queries Windows GPU Process Memory local-usage counters matching its PID. Missing driver counters are `UNAVAILABLE`, invalid measurements `INCONCLUSIVE`, and measurements are labeled **OS observed only**. `gpuQuotaVerified=false` always: no enforced VRAM admission, no absolute adapter memory claim and no GPU-free assertion.
- **Restart correctness:** Native physical restart now checks the new process creation FILETIME rather than rejecting valid PID reuse.

These changes improve defensive groundwork and verifiability but cannot be called complete sensitive-region detection, approved screenshot delivery, physical installed acceptance, or production GPU resource management.

## P06 exact-source OS/UIA sensitive-surface diagnostic (2026-11-06)

Added `scripts/probe-observe-sensitive-window-windows.ps1`: a read-only, independently queryable Windows accessibility adapter for one explicitly supplied HWND/PID/process creation FILETIME. Native Win32 verifies the HWND is root, visible and uncloaked and belongs to that same process instance; OS UI Automation returns a bounded set of `IsPassword` control rectangles, without accessing their names or values. It rechecks process lifetime after the query and refuses invalid bounds. The rectangles are in **desktop coordinates, not attested WGC image coordinates**. The receipt always states `INCOMPLETE_UIA_ONLY`, `wgcFrameCoordinatesVerified=false`, and `pixelReleaseAllowed=false`; custom-rendered secrets, images and inaccessible/protected controls remain undetected. This creates a real OS privacy signal, **not a certified selective redaction engine**. Live captured frames remain fully blanked.

## P06 native foreground visibility and installed relaunch (2026-11-06)

- **OS source admission** now requires top-level root HWND, actual OS visibility and zero DWM cloak status, in addition to HWND/PID/process-creation FILETIME. The foreground worker checks this at human-focused selection and before/after D3D11 readback. Read failures are hard denials, never a fallback to generic monitor/unknown-item capture. - **Installed native restart trial** uses explicit \`-InspectObserveUi -ExerciseRestart\` with reviewed exe/worker digests. It terminates the first real Lu process, checks directly owned capture children, launches a second native OS process, independently checks UIA root PID, and records a scoped UIA OFF finding or an INCONCLUSIVE result. It does **not** prove durable TaskStore grants, a real crash, installer install/uninstall or visual content.
- **Boundaries**: Generic WGC picker still lacks OS source identity and remains full-frame-blanked. Sensitive-region detector/pixel bridge, human physical WGC, NSIS cycle and independent visual GUI/effect proof remain OPEN. Source/CI work is not installed acceptance.

## P06 installed UIA and worker lifetime attestation (harness source only)

The operator-run installed harness now requires Windows UI Automation's root PID to match the genuinely started hash-reviewed Lu process, rechecks after Start/Pause/Resume/Stop and checks the exact earlier observed WGC child PIDs are no longer alive after Stop. A changed worker name or parent cannot by itself produce a false OS-reap PASS. These additional independent OS checks are unexecuted on a physical Windows desktop and do not establish OS picker selection, semantic vision, NSIS installation or region-safe redaction.

## P06 foreground OS identity after D3D11 readback

The explicitly approved foreground-only mode now checks HWND, owning PID and OS process-creation FILETIME **both before D3D11 frame mapping and again after frame-buffer release but before publishing the worker's stdout receipt**. A source/process replacement between those points now stops the capture and rejects the receipt. This narrows an earlier time-of-check/time-of-use window, but it cannot prove same-window HWND generation within one process, distinguish the generic picker, or certify image content. The direct Windows callback still needs native compile and physical acceptance on the exact head.

## P06 selective-region masking engine foundation (source only, NOT pixel-release acceptance)

A bounded BGRA rectangle-mask primitive is now compiled in the Windows capture-worker crate. It validates **every** proposed region before writing, rejects an empty mask, more than 4096 regions, overflow/out-of-frame coordinates and invalid strides, masks four bytes per pixel without modifying D3D row padding, and tests that a late invalid rectangle leaves the entire original buffer unchanged. This is **only the deterministic sanitization algorithm**, not verified sensitive-data detection. A native trusted Windows accessibility/surface classifier still needs to bind each region to the actual HWND/process instance and validate that every confidential surface is covered. Arbitrary model/renderer/UIA hints cannot grant pixel export; when region evidence is absent, the current live WGC path continues to hash only a **fully blanked frame** and retains no pixels. No new model image bridge, recording, screenshots or selective preview have been enabled. Cross-platform Rust behavior and actual Windows native compile remain CI-gated.

## P06 supervised receipt gate and opt-in native worker reap trial (2026-11-06)

- **Native receipt gate:** A terminal TaskStore row and plausible SHA-256 alone can no longer produce a successful one-shot receipt while the OS supervisor still owns a cancellable live worker. `ObserveHost::capture_receipt` requires **all three**: task `Completed`, validated digest, and supervised process no longer active after a successful `poll`. On uncertainty `image_received`, `fully_redacted_receipt`, `source_identity_attested` and `frame_sha256` are withheld; Guardian custody is retained. A focused Rust regression enumerates all negative combinations.
- **Optional physical Windows worker cleanup trial:** `scripts/verify-observe-installed-windows.ps1 -InspectObserveUi -ExerciseObservationLifecycle -ExerciseCaptureCancellation` (with reviewed EXE/digests) uses native Windows UI Automation to request the one-shot picker, requires the **human** to approve the independent Lu-native dialog, and observes a real child process with the exact installed worker path and Lu parent PID through Win32 CIM. It then invokes the installed Stop action and requires that owned OS worker disappear; records only `PASS_OS_CHILD_REAP_ONLY` or explicit INCONCLUSIVE/FAIL. It never approves the dialog, captures pixels, asserts the OS picker was presented, certifies sensitive-region masking, or pretends a physical trial has been executed in CI.
- **Remaining:** An operator must actually run the installed trial; true source attestation for arbitrary picker selection, selective trusted secret-region redaction, meaningful model pixel transfer, external GUI effects, installed NSIS install/uninstall, hardware telemetry and independent WGC cancellation evidence remain open. The current unrestricted generic picker is ephemeral, unverified and fully blanked.

## P06 scope: privacy before active vision

P06's priority is *OFF by default; explicit human consent; event-driven, bounded native observation; visible pause/stop and revocation; provenance-marked verified evidence; human-reviewed handoff*. Not a continuous screen recording, always-running transformer, autonomous training, or an AI with unsupervised OS access.

### Already present and reused

- `native_observe_learn` controller denies events without explicit consent, enforces a 30-minute current Lu-only scope, allows pause/resume/stop, expires grants, bounds event rate and never automatically writes memory.
- `native_observe_scope` restricts window/app/monitor/virtual-desktop targets; renderer hints are never trusted OS identity or source proofs.
- `native_awareness_lane` runs cheap native event classifications with explicit renderer/native/runtime/test provenance and deduplication; small model and main model handoff remain recommendations, not automatic inference.
- `ObserveHost` reuses native TaskStore, BackgroundProcessSupervisor and the current desktop; read-only notes and handoff exist. Single-frame Windows WGC capture remains separately prompted and process-supervised. Receipt hash alone is neither a verified source identity nor a model visual interpretation; no raw pixels are retained in the normal Lu pilot.
- `native_gui_verification` compares intended source/artifact digests against *independently attested* GUI/test evidence, returning PASS/FAIL/INCONCLUSIVE. Real independently operating Windows WGC/GUI test proof is still an acceptance gate, not established by the comparator itself.
- ANSF publication remains separate, off by default and human-reviewed. No renderer event or model suggestion can independently publish memory, run code, or start training.

### New implementation on this P06 branch

1. **SQLite source provenance repair:** previous `lu_awareness_notes` CHECK constraint recognized renderer/accessibility/native-test sources but *rejected native-runtime source values* that the trusted ObserveHost already emitted. New installs include the genuine source. Existing installs perform an atomic copy/rename migration preserving old rows and recreating the scoped index before they can append native-runtime notes. Native failure is an **unverified runtime indicator**, not a GUI test verdict.
2. **Bounded metadata retention:** enum-only awareness rows automatically expire after **seven days**, pruned at TaskStore open and each consented notes/handoff read. Retention is logical SQLite deletion; never claim forensic erasure of old WAL, backups, previously copied prompts, or chat history. No screenshots, paths, app contents, prompts, or key presses enter this table.
3. **Per-chat forget:** native `lu_observe_forget_notes` command checks a real existing conversation, prompts with a **native confirm/deny modal**, and invokes `TaskStore::delete_awareness_notes_for_workspace`. SQL filters by exact chat and `obs-%` task identity. An explicit cancel is distinguished from confirming zero notes. This does NOT delete independent task lifecycle/audit records, ANSF memories, copied text, ordinary chat messages, or live capture processes.
4. **Prevent stale handoff after forgetting:** ObserveHost clears current-session counts and invokes `AwarenessLane::discard_observations` when deleting current chat notes. This clears volatile note and suggestion history but **does not rewind monotonic event sequence**, preventing replay. Observation scope and consent do not widen or auto-start; a new event requires the same live host grant.
5. **Visible review:** the React observer pane exposes Forget for active/paused and off sessions, reports seven-day retention, clears stale locally rendered notes/handoff on confirmed deletion, and leaves native Capture/Model/ANSF authority unchanged.
6. **Tests:** P06 native tests cover existing SQLite schema migration, trusted native-runtime insertion, chat-isolated deletion, TTL pruning, no stale review or replay, and native host provenance. New Node contracts check the actual Tauri/React wiring. Focused `.github/workflows/lu-p06-observe-privacy.yml` compiles/tests Lu Core on Windows and Linux, builds React and checks/tests the Windows desktop host, without faking an inference engine.
