# CP-06M-R1 — semantic retrieval, corrected sources and cross-process continuation

Local-only continuation of CP-06M (`d59eea5bb6562a071a534fd78e308645f9dfcb96`). The published application source ref is not advanced by this work. Existing hosted acceptance obligations remain separate.

## Implementation

Authenticated ordinary Send now includes indexed earlier messages in the active conversation as well as other saved conversations. The current human turn, future same-conversation entries and identical earlier user questions are excluded before the bounded semantic ranking. Current revisions are checked at selection and reopened immediately before ordinary memory context is formatted. Explicit historical source lookup still accesses immutable superseded originals. A final current-turn identity check rejects a turn that changed during retrieval. These are bounded source-read checks, not a claim that an external fact remains true or that the database cannot change after the prompt is prepared. Recalled text cannot transfer authorization, custody, completion or retry authority.

The local embedding worker has an explicit bounded context allocation. The optional human-controlled related-message setup is now reachable from Settings > Memory. A selected local model still requires native picker/confirmation; only an explicitly chosen conversation is prepared, in bounded batches. Derived vectors remain stored across restart, but enabling the worker is session-local and requires fresh human action. No engineering identifiers, model-facing tool controls, or raw index diagnostics are exposed in the new settings panel. Lexical memory remains available without the optional worker.

## Acceptance design

The genuine native desktop fixture invokes itself in three independent processes using one saved profile. Phase one computes actual embeddings, indexes an original source, appends a human correction and indexes the new revision, records a checkpoint, and appends enough intervening messages to put the source outside the recent-history window. Phase two opens the saved profile and loads the pinned local model again. A paraphrased question that does not obtain the reference via lexical recall must rank the corrected source first among four eligible passages. Repeated identical questions and the superseded source must not compete; exact historical navigation must still reopen the old source. The two memory cases (same and other conversation) must recover the corrected reference, with the old one absent. A third ordinary-turn continuation case must recover the saved next step with no execution authority. All three answers must be genuinely generated via the native supervised GGUF backend, persisted, and verified by a third independently launched process. Synthetic source data only; no external egress or live effect required.

The fixture uses the already retained Qwen3-0.6B Q4_K_M chat model in mean-pooling embedding mode, not a dedicated embedding model. It qualifies the bounded corpus and real-vector path; it does not establish broad relevance or performance superiority, cross-model portability, full large-history coverage, graphical interaction, physical Windows installation, or automatic model reload. The actual rerun receipts record results separately. Full graphical memory workflows remain in CP-06F/CP-10 and comparative ablations in CP-09M.
