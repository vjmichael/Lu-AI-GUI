# CP-11B-R1 — Scheduled local model responses

First bounded task scope: review a single-line prompt, conversation, actual ready registered model, initial delay and recurrence through native approval in Tasks. The approved immutable schedule permits text-only inference on that model ID (not a content hash), not arbitrary tools or stored conversation context. No auto-load, no model-controlled scheduler, no automatic shell, file or network operations. Native watchdog reuses resource admission, model-profile fence and idle-only generation reservation. A chat queued before admission wins; one already-started occurrence is bounded to 128 output tokens, a cancellation request after 35 seconds, and 16 KiB returned UTF-8 bytes. It yields the model slot before another occurrence; an explicit Cancel may eject the engine. No hard real-time bound on OS reaping is claimed.

SQLite journals claim and cadence in one transaction; one running occurrence maximum, no stale or double terminal writes. Missed repeats coalesce to the latest due occurrence when the approved model is ready; no backlog storm. An interrupted claim is marked interrupted on next owner startup, with no replay of that claim. Future recurring occurrences retain original text-only consent. Pause applies between attempts; cancel stops current and future occurrences, discards partial output. One-shot terminal results do not retry. Owner-scoped result retrieval displays generated text as inert text, not a verified factual answer. Up to 64 retained schedules and 32 attempts each; no automatic deletion. Calendar/DST schedules, background service while Lu is closed, natural-language task proposal, tool-authorized scheduled execution, retention cleanup and Windows/physical qualification remain separate gates.
