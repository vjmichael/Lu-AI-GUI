## Architecture and candidate disposition

Lu's existing Rust `InferenceBackend` + Protobuf `InferenceBridge` + `TrustedInferenceSupervisor` are the **single authorized host/model/tool boundary**. The original `PersistentLlamaBackend`, pinned `llama-server` CPU/Vulkan binaries, GGUF/MMProj admission, source-pinned file digest checks, streaming, P2 KV invalidation, P3 interruption recovery, P4 interactive priority, P6 default offline and OS process custody remain unchanged.

The installed `lu_model_select_backend` still selects **CPU or Vulkan only** in builds supporting the dual-engine preview. The Settings backend inventory now includes three **nonselectable** research candidates (not installed and not independently verified). None can dispatch a prompt, launch a process, access source files, load models, authorize tools or join existing sessions. Single-GPU offline operation remains first-class. Runtime automatic fallback to an alternative is explicitly prohibited: after an authorized tool action, a silent retry could duplicate effects.

## Implemented source work

**1. Native candidate preflight and immutable identities.** New `src-tauri/lu-core/src/p7_backend_evaluation.rs` contains explicit `CandidateKind` (`mistral_rs`, `koboldcpp`, `vllm_gguf`), `CandidateManifest`, `VerifiedCandidate` and `NativeConformance`. All candidate executable and original GGUF bytes are hashed against a nonzero owner-supplied SHA-256 under strict 1 GiB executable and 128 GiB model scanning limits, with original read file handles retained. A model's original `AdmittedModel` metadata is rechecked. If a projector is involved, exact independent MMProj SHA-256 (max 16 GiB) and the canonical admitted projector path are mandatory; no silent text downgrade or swapping projector identity. Symlinks and nonregular files are refused. This is **evaluation preflight**, not permission to execute the binary or proof of correct DLLs, dependencies or no post-hash path replacement race.

**2. Original inference surface guards.** `EvaluatedInferenceBackend<B:InferenceBackend>` wraps an independently implemented original native backend, not an arbitrary HTTP endpoint or new app. Its constructor refuses a candidate unless a complete native **text** conformance record is independently obtained: exact process custody, authenticated loopback, loaded original GGUF, bounded SSE, role/history isolation, native cancellation/reaping, and restart reconciliation. It bounds ordered token chunks to 64 KiB and total visible output to 1 MiB and detects malformed order, NUL, cancellation or empty output. New projector-backed generation additionally requires verified MMProj proof and an actually loaded original projector. Structured read-only tool calls require separately verified structured schema and one-use authorization (existing schemas, never parsed model prose). P2 KV scope reuse is disabled unless exact trusted cache-identity behavior was independently verified. `NativeConformance::production_selectable()` and `EvaluatedInferenceBackend::candidate_can_replace_production()` always return **false**: evaluation testimony cannot turn itself into a production grant.

**3. Original desktop operator inventory.** `lu-desktop/src-tauri/src/lib.rs` reports the candidate names as `packaged:false`, `selectable:false`, `runtime_inference_verified:false`, `gpu_execution_verified:false`. Existing legacy `vllm` inventory id is preserved. The host-owned CPU/Vulkan backend selector remains unchanged, without external executable or user-supplied network URL admission.

**4. Strict paired repeat analyzer.** `scripts/perf01-p7-backend-comparison.mjs` reads a small local JSON receipt file with exact 40-hex **source head**, engine SHA-256 for BOTH baseline/candidate, full original GGUF SHA-256, fixed suite SHA-256, machine ID, matching context length and optional exact projector SHA-256. The six case IDs are `text_exact`, `text_code`, `vision_mmproj`, `structured_tools`, `cancel_stream`, `restart_recovery`. At least five paired source trials of **both** text and code are mandatory. An included case needs five to twenty exact matching trial IDs for both runners. Vision requires an original projector digest. Duplicate, missing, stale, malformed, negative, contradictory and out-of-bounds inputs are rejected. Reports per-case TTFT-to-first-forward p50/p95, total p50/p95, approximate decode throughput **only when original decode duration and tokens were measured**, basic quality counts, cancellation/recovery counts, and explicit missing cases. The output always reports `installedBackendPromotionAllowed:false`, `physicalOwnerAcceptance:false`, no independent hardware/process/model/VRAM attestation and `performanceImprovementAccepted:false`.

**5. Ignored synthetic real-loopback probe.** `src-tauri/lu-core/tests/perf01_p7_candidate_protocol_real.rs` is owner opt-in and not run with normal test execution. It requires a separately started, OS-reviewed candidate server on a **loopback port** and a 64-hex test key, plus real local model/engine digests and admission. It tests the original Lu role/history request builder and bounded chat SSE reader using **fixed synthetic prompts only**, hashes responses, measures first host-forward/total time and probes client-side abort. It does **not** prove the listening process is the SHA-pinned executable, TLS authentication, actual native cancel/reap, image accuracy, tool safety, performance superiority, or source-file authorization. This probe can detect protocol incompatibility but cannot approve a candidate for product use. Original user data never enters it.

## Unresolved engineering gates (P7 remains OPEN operationally)

1. **Candidate packaging and custody:** Choose *one* independent candidate (prefer the lowest-dependency local offline GGUF candidate after owner review); pin exact executable plus dependent DLLs/shared libraries and licenses. Verify OS admission and process tree cleanup before connecting its loopback interface to the original host. No automatic provider downloads, MCP, Docker, shell execution or unreviewed dependencies.
2. **Original API/IPC implementation:** Implement a candidate-specific concrete `InferenceBackend` using the existing original Rust/Protobuf host and trusted queued generation. Verify auth, port ownership, GGUF tokenizer/quant support, stable role/history, partial chunk delivery, cancelled stream/disconnect and restart reconciliation. Do not route tool prose as commands.
3. **Multimodal/tool capability:** Validate exactly the same original GGUF and MMProj bytes and tests; prove real image comprehension, tool call JSON schema constraints, source-only/browser approvals, rejection of malformed stream events, cache invalidation and zero trust-boundary regressions.
4. **Genuine repeated A/B tests:** On the same machine/source SHA and verified pinned model version, alternate baseline/candidate across fixed text, code, vision, tool, cancelled and restart cases, 5–20 pairs per case. Compare p50/p95 TTFT, decode throughput, total latency, RSS/VRAM peaks, energy if available, bounded concurrency, semantic/functional correctness and deterministic trace of authorized effects. A candidate must not win merely by omitting output, losing vision, changing tokenization or bypassing tool checks.
5. **Independent acceptance/promotion:** No built-in `selectable:true` alternative before a separate owner-approved exact-head native and installed acceptance with P0-SEC, P1 residency, P2 cache, P3 stream/journal, P4 fairness, P5 tuning, P6 optional GPU and physical Windows Linux regressions. Keep the original pinned llama.cpp backend always available as fallback. An interrupted candidate turn must not be silently replayed on fallback.
