## How to interpret this register

**Source priority:** current explicit owner instructions > later owner-confirmed decisions > current source and canonical design docs > prior approved design > proposals > historical assistant assertions. Every item below names a decision and approximate date; chat references are **not verbatim archived transcripts**. If evidence is incomplete, label it. An AI must retrieve an original message or inspect the current repository/CI before making source-specific or implementation claims. A later correction changes the active decision, not the text of the original event.

## A. Foundational ANSF decisions — binding approved direction

| ID | Owner decision and chronological basis | Consequence for implementation |
| --- | --- | --- |
| ANSF-01 | **2026-10-25 and reconfirmed 2026-11-07:** effectively unbounded, model-independent conversation memory using ANSF + SQLite as canonical durable source; exact original message text and order persist. | No summary-only, embedding-only, or temporary JSONL authority. Prompt context is a bounded *view* into durable disk-backed history, never the whole archive. |
| ANSF-02 | **2026-10-25:** human Library → Book (conversation) → Chapter (topic) → Page (staged text block) → original entry navigation. Summaries and labels are metadata, *not* substituted originals. | Human-readable pages render text from binary SQLite; library/catalog has metadata and source references rather than copied original transcripts. Pages are a navigation/windowing abstraction; do NOT invent an arbitrary mandatory book rollover or treat a page summary as a fact source. |
| ANSF-03 | **2026-10-25:** exact text is retained and searchable, with durable host-minted message/source IDs; **2026-11-07 refinement:** a known source ID should resolve with one authorized direct lookup, not three exploratory index hops. | Use direct source IDs first; Library/chapter FTS5 and later optional semantic retrieval discover unknown sources. Every retrieved candidate is re-read from the original ANSF book and authorization checked. |
| ANSF-04 | **2026-10-25:** a separate Memory Worker/search/history pane must browse independently of live chat. Search/opening historical entries cannot replace the active conversation or reset its composer, output, queue or position. | Do not mistake a small inline Recall widget for fulfillment of the approved independently navigable history pane. |
| ANSF-05 | **2026-10-25:** bidirectional virtualized/windowed scrolling with stable cursor/page IDs and staged neighboring blocks creates the illusion that the entire multi-month/year transcript is present. | Load neighboring pages on demand, unload far-away rendered rows, preserve viewport anchors. Do not read/materialize all history into WebView or the model prompt. The archive remains available regardless of UI eviction. |
| ANSF-06 | **2026-10-25:** cross-chat selection/linking/transclusion should refer to original entries without duplication; preserve the **source purpose versus destination purpose**. | Linked messages are cited historical context in the destination, never new system messages, current user instructions or inherited effect grants. Track parent/source identity and provenance. |
| ANSF-07 | **2026-10-25:** edits append a NEW immutable entry and link original→previous→current; original wording and all versions survive. Human-visible date notation was requested as 'Edited · MMddyyyy HH:mm:ss'; import-observed changed snapshots must not impersonate trusted direct edits. | Source revision chains and timestamps, visible compare/version navigation, current-vs-historical resolution. Imported updates are labeled 'Source update detected'; import time is not proof of human edit time. |
| ANSF-08 | **2026-10-26:** lightweight Context Change Monitor (CCM) is part of ANSF-integrated context/continuity, not a competing subsystem. Detect goal, assumption, scope, constraint and evidence changes without silently discarding completed work. | Belief/intent revisions require provenance, conflict labels and refreshed action authority where goal/scope changes materially. |
| ANSF-09 | **2026-10-26:** user-approved, append-only, project/task/conversation-linked continuity checkpoints referencing verified ANSF original entries. | Carry actual goal, decisions, completed work, blockers, next action and receipts across chat/model/restart. Continuity/context never grants executable authority. Existing Lu Core ContinuityStore is the source implementation base; live desktop acceptance may lag. |
| ANSF-10 | **2026-10-28:** freeze ANSF core architecture; proceed with tests and integration, not another overhaul. | Repair original architecture; optional derived search indexes do not justify new canonical stores. |
| ANSF-11 | **2026-11-07:** SQLite records are native structured relational memory; Protobuf is internal IPC for modules/tools/workers; JSON may be at model/Tauri/API/import boundaries. Historical JSONL was transitional, not desired canonical message storage. | M2 ANSF-native SQLite cutover and non-destructive JSONL migration supersede earlier provisional JSONL-as-authority documents. Imported old turn IDs are never freshly authenticated grants. |
| ANSF-12 | **2026-11-07:** multimodal blobs and large artifacts/packages remain outside ANSF conversation SQLite; keep verified opaque, source-linked references only. | Preserve image/document/video/audio/installer bytes in separately managed storage; revalidate integrity and availability at access time. No large base64 or binary payload in original conversation DB. |
| ANSF-13 | **2026-11-07:** explicit Yes / No / Not now and optional comment for relevant user clarification; Not now is not yes, no, consent or tool approval. | Persist user-goal/clarification provenance and deferred/pending state; never re-ask a resolved question just because a new conversation started. Maintain current per-turn host authority separately. |
| ANSF-14 | **2026-11-07:** require three-arm real GGUF benchmark: stateless/no persistent memory, ordinary recent chat/history, and full ANSF; same hardware/model/quantization/settings/task/tools. | Score correct decisions, source fidelity, task success, repeated discovery, false recall, latency/energy/storage, restart and tool-authority errors. Baselines and negative results must survive. S1–S4 semantic extensions are additive; synthetic vectors aren't semantic-quality evidence. |

## B. Memory is more than stored messages

The approved goal is to make any model *waste less time rediscovering* known source evidence and completed work. Do not conflate distinct records:

| Layer | Persistent responsibility | Trust and freshness |
| --- | --- | --- |
| **Immediate/working** | Bounded current conversation, active goal, constraints, latest source windows, unresolved questions | Exact current user-turn provenance; prompt is a cache, not archive or grant. |
| **Episodic** | Original messages, what was attempted, observations and verified/failed outcomes | Immutable ANSF entries and independent journal receipts, with source IDs and timestamps. |
| **Semantic/belief** | Source-derived facts and object relationships, current interpretation, conflicts, superseded decisions | Rebuildable projection; explicitly distinguish verified, inferred, uncertain and outdated; source recheck on read. |
| **Procedural** | Reusable workflows, tested environment prerequisites, commands, failure modes, success receipts | Versioned, validated, non-authorizing recipes; revalidate software/files before execution; do not promote speculative summaries. |
| **Operational/continuity** | Task scope, completed and pending operations, checkpoints, artifact manifests, worker/effect states | Trusted host journals/ContinuityStore remain authoritative; UNCERTAIN effects require reconciliation and **must not be blindly replayed**. |

**Critical correction about operational memory:** user conversations and canonical handoff clearly approve the outcome (no user-as-session-transport; source-linked checkpoints). A 2026-11-01 detailed **DPCA/asset-ledger schema** was explicitly a *design proposal, implementation not accepted*. The current user has reiterated build-asset reuse and zero repeated NSIS environment discovery as a primary product requirement. Thus **the outcome is now confirmed**, but don't misstate an old DPCA schema as previously approved or claim production code already implements it.

### Operational continuation scenario: real Windows NSIS builds
Preserve the last exact source commit, verified Windows SDK/MSVC/LLVM/Rust/NSIS toolchain versions, package ZIP hashes and local provenance, resource locations, unpacked/staged directory manifests, pinned llama.cpp engine/DLL identity, build recipe, last finished operations/test evidence, known blockers and next executable step. Packages stay outside ANSF; metadata links to verified host-owned artifacts. On a **new chat**, revalidate availability/digest/version, then do **only missing work**. Missing resources can be reacquired, but never blindly rebuild everything based only on lost conversational context. A path remembered from an ephemeral runtime is *not* evidence the bytes still exist.

**No lazy-summary substitution:** summary/chapter metadata may guide retrieval, but task resumption must check the exact original entries, durable receipts and current actual environment. Two quick topic changes must not be flattened into one fabricated common decision.

## C. Other binding Lu directions that future assistants repeatedly miss

1. **Human-centered model effectiveness (2026-11-07):** Lu should make model capability practically useful to users of varying expertise; clarification and memory are part of the feedback loop, not a substitute for the user's goals. Do not mistake fewer tools, less effort or shorter summaries for better task outcomes.
2. **Lu-independent desktop (Oct–Nov):** Tauri/React, Rust Core, locally managed GGUF+MMProj with llama.cpp, AMD Vulkan plus measured fallback; Jan is an import/UX reference, not runtime dependency. A single-click Windows NSIS app first, not Docker/multiple manual installs/mandatory CLI.
3. **Native tools and true authority:** first-party Protobuf tool/worker channels, MCP optional. Tool discovery ≠ authority; models, recalled chat, attachments, web pages, tools or subagents cannot self-authorize. Human-task-specific host grants, revocation, durable effect journals and process supervision are separate; do not replay uncertain effects.
4. **Multi-model continuity:** task and memory must survive model replacement; exact KV cache persistence is not a prerequisite. No automatic hot swap, claimed inference, or invented progress.
5. **Conversation UX:** cross-chat queued generations, surviving streaming and cancellation partial text, per-chat drafts, accurate Received/Processed/Applied receipts, inspectable source provenance, independently navigable history and user-friendly GUI. Do not mix output across chats.
6. **Context change and memory editing:** owner corrections, assumption changes and supersession should preserve original records while changing the *active* belief/plan. Human 'make primary' and link-selected-content options are desired UX; implementation acceptance must be independently verified.
7. **Development/release workflow (2026-10-31, 2026-11-03):** disposable/headless Lu Dev worktree, Lu Main/Stable protected; tests and merges alone cannot replace stable. Alpha 0.1.0-alpha.2 was owner-accepted as functional development baseline, not v1.0 release. GitHub is repository/CI evidence, not user's development hub. Avoid blocking development solely on queued hosted jobs. Later physical installed Windows/AMD acceptance remains a distinct gate.
8. **DLC scope:** Lu Core first, then IDE / Film (NVP) / Research / Writing workspaces. Cognitum remains an optional add-on, not permanently embedded in general Lu Core. Do not force DLC interfaces before the v1.0 contract is mature.
9. **Observe & Learn:** OFF by default with explicit activation and experimental warning; observation is not remote viewing or a standing permission to capture everything. Provenance, scope and additional permissions matter; earlier approved controls included visible user consent and platform-specific host/admin enablement.
10. **Native tools prioritization (2026-11-06):** favor integrated, AI-effective tools over cloning whole desktop products. Read the ordered tool priority ledger before inventing a new native tool area.
11. **Scope corrections:** earlier mandatory sandbox/strict workspace-root suggestions were superseded by controlled real-host access with task-scoped authority; A/V/media and DLCs were deferred while memory/core were built; current owner instructions supersede stale early checklists.

## D. Important unresolved choices and status boundaries

- **Not yet established as final decisions:** complete retention/purge/backups/tombstone policy, cross-user ownership/export/authenticated memory lease semantics, automatic semantic model choice and package, exact S1–S4 performance thresholds, optional vector/HDC research; the earlier DPCA schema itself was only proposed.
- **Not yet delivered by the current M3 source:** independent historical search pane separate from active chat; true cursor-virtualized infinite-looking transcript; automatic verified procedural/operational asset reuse; full context-change monitoring/continuity integration into Send; live offline embedding model for S3; three-arm real-model result for S4. Basic M3 Recall UI is an inline prototype.
- **M2/M3 are draft/source changes:** CI success on a prior head and synthetic native fixtures are not proof of latest-head Windows/Linux gates, successful real installed GGUF migration or physical NSIS lifecycle. Recheck branch, SHA and Actions before reporting accepted gates. Distinguish later owner instruction to move from M2 to M3 *development* from declaring all M2 release tests passed.
- **Historical conflicts:** early JSONL authority is superseded by the 2026-11-07 M2 canonical ANSF cutover; historical numbered-Protobuf pages should not replace SQLite canonical books; library summaries never outrank original text; 2026-11-04 bounded model-boundary JSON repair supersedes older blanket repair deferral; 2026-11-03 acceptance of alpha.2 supersedes older alpha NO-GO checklists for that same functional baseline, not v1.0 release.

## E. Continuity protocol for every new Lu development session

1. **Read this register first**, then [central design](LU_CENTRAL_DESIGN.md), [Lu 01–21 handoff](LU_CANONICAL_HANDOFF_CONVOS_01_21_20261103.md), current [M2/M3 evidence ledgers](LU_M3_CROSS_CONVERSATION_RECALL_20261107.md) and [v1.0 tasks](LU_V1_0_TASKS.md). This document is an *index/decision map*: retrieve exact original source and current code for any contested detail.
2. Identify the **current** repo/branch/PR/exact head, active phase, source-tree lock, genuine CI/installed-app evidence and unmerged stack. Do not use stale commits as today's state.
3. Retrieve already-known decisions and verified assets *before* re-planning or searching/downloading resources. Inspect files/hashes in the current environment first; expired/missing references must be reported and repaired, not assumed.
4. Keep original user decisions distinct from assistant recommendations and from subsequent code acceptance. Never promote prior assistant claims of 'completed' without tests or original evidence.
5. Preserve task/effect authorities, privacy/consent and current user scope separately from memory context. No old user-turn ID, recalled snippet or summary authorizes effects.
6. Append only significant owner-approved changes or verified engineering evidence with date and new provenance. Preserve superseded wording and link correction instead of rewriting history. If the original conversation is unavailable, clearly mark the synthesized record *provisional* and request exact source only when a material ambiguity cannot be resolved otherwise.

## F. Incompleteness and provenance

This register reconciles **accessible** previous Lu/Lu Dev conversation records (not all original message bytes or every named Lu Dev chat), the November 3 recovered *Conversations 01–21* handoff, central design, the ANSF roadmap, and current November 7 M1–M3 source. It does **not** claim to have read every Lu conversation in full. For exact message-by-message fidelity, Lu must ultimately preserve and index the original imported history itself; ChatGPT's cross-conversation retrieval is not a replacement for that archive. Do not cite this synthesized register as proof that a particular historical quote was spoken verbatim.
