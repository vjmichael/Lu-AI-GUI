# CP-12B-R4-R1 — Installed collaborative troubleshooting crash recovery

Date: 2026-11-20 UTC. Scoped installed Linux acceptance, not a release.

## Decision and implementation

The previous lifecycle fixture exhausted the existing durable start circuit (two starts per five minutes). Restart admission, security, and production source remain unchanged. The new installed fixture `scripts/cp12br4r1-crash-recovery-gui.py` separates independent fault scenarios into disposable profiles, and preserves each same profile and its original durable start ledger across each crash. It witnesses actual owned inference-worker CPU activity, real application process termination, worker reaping, unchanged diagnostic evidence, no automatic model loading, explicit user loading, native consent, one-use invitation rejection, fresh verified exchange, and model inactivity on stale/replayed invitations. Ledger evidence is read-only; no clock adjustment, reset of admission state, or private application IPC. Invitation codes remain transient and are not recorded. Clipboard ownership is retained only to exercise crash/replay. A dead test endpoint, if left by the OS, is removed only after the stale invitation is refused; this is not a claim of automatic cleanup of abandoned endpoint directories.
