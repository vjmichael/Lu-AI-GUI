## Source and design

Restored prior `d54590c2b5fc94811b6df20c208a69f31f8d12ab` with 1,243 entries verified. Application source `cfadeb517baf67a80f991d17c8079d0e727ad539`, 1,246 entries verified. Reuse the existing authoritative `localize_transactional_turn` over the validated native archive; no new diagnostic archive, tool authority, network access, or dependencies. Project at most 64 recent records into original five outcome totals plus sorted numeric counts at 25 known checkpoints and one unknown bucket. Observed stop/failure and first-unconfirmed boundary counts are distinct; incomplete, recovered, conflicting and unavailable traces never become confidently localized. The count sums must exactly reconcile with the original summary. Unknown or missing evidence precludes a unique finding; multiple affected steps are not reduced to a single cause. Intentional refusal/stop is not necessarily a malfunction. No per-record identifiers, timing, raw error messages, private data, routes to files, free-form output, or model identity in the exchange.

Version 3 is a separately approved one-use same-account local exchange. V1/v2 remain available (original bytes for v1 and old v2 validator preserved). The existing endpoint lifetime, authentication, canonical encoding, cancellation, revocation, peer isolation and publication gate are reused. The sender and receiver each use only their already-loaded local model with an empty history, bounded generation and no tools. The receiver model does not see the sender model's answer; both must match a deterministic verdict over the same valid evidence. This is independent classification and consistency checking, not independent observation of the sender's actual actions or proof of its integrity. No automatic repair or model loading. Windows v2/v3 collaboration remains disabled. Settings presents a separate affected-step review action, human labels and fixed local next checks.
