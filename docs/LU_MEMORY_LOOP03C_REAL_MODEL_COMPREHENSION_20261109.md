## Work implemented

The real desktop `memory_loop03b_context.rs` Rust test opens original ChatStore, ANSF, ContinuityStore and EffectJournal files and invokes `for_current_human_turn` on four authenticated original human requests: unavailable versioned procedure with unknown OS custody, missing source-backed belief, missing comparable CCM checkpoint, and a pending goal clarification dominating remembered procedures. Each capsule is checked against independently specified negative expectations and written when `LU_MEMORY_LOOP03C_NATIVE_FIXTURE_PATH` is supplied. Its 03A gate labels are **test inputs**, not a real OS or current-goal witness. No positive independently verified procedure, belief, source revision, or actual native tool effect is claimed.

The new `benchmarks/e1/memory_loop03c_real_qwen_comprehension.py` requires this actual native corpus schema, with original current-human identifiers, non-authorizing state, no source freshness claim and no reused grant. It runs the same checksum-pinned real Qwen3-0.6B GGUF using the same seed and inference policy in two arms: (A) original source evidence plus goal/recovery labels without the host decision; (B) the full host-classified 03B capsule. Strict model-response JSON validation rejects duplicate keys, extra tool requests, malformed fields and fake completion. Scores distinguish **model-format/interface**, **Knowledge/source status**, **Authority/unsafe action**, **Feedback/OS or freshness overclaims**, and **source-only context insufficiency**. Preserved raw response SHA, latency and optional token counters allow audit. No model output is generated by fixtures or a mock. Missing actual engine/GGUF fails rather than producing a green result.

The existing manual `lu-memory-loop03b-native.yml` adds genuine Rust corpus export, Python policy regressions and source validation in its Windows/Linux matrix. Optional `run_real_qwen=true` runs pinned llama.cpp + actual checksum-verified Qwen3-0.6B on Ubuntu **only at the end of the task group**. Workflow checks are source-proposed, not executed.

## MEMORY-LOOP-03C-G4 — real test-only Git oracle / positive memory corpus (source candidate)

The new native ansf_chat_store::memory_loop03c_positive_oracle_tests runs **two independent direct OS Git HEAD commands** on an actual temporary Git repository, recording the first observation as a test APPLIED receipt and the second as the separately hashed GIT_HEAD_DIRECT_V1 outcome in Lu's **real EffectJournal**. It then constructs the original human AnsfStore source and ContinuityStore checkpoint, promotes a version-matched verified procedure and a source-linked Claim, and feeds current authenticated human selections through the **actual 03B model-facing host reader**. Six source cases are independently asserted in native Rust:

- Historical observed Git procedure and belief: HISTORICAL_SOURCE_ORACLE_VERIFIED_* at observation only, no current source check or inherited grant.
- Pending goal clarification dominates a historically verified procedure; human review required.
- Version 2.0 cannot recover version 1.0 tool procedures.
- A later original human correction invalidates the historical procedure.
- An original human retraction marks the independently observed Git belief retracted, not current.

A separate memory03c-positive-git-corpus.json can be exported through LU_MEMORY_LOOP03C_POSITIVE_FIXTURE_PATH. Its schema **explicitly labels the witness as test-only direct Git OS commands**, not a production reviewed application worker; it records the original 40-character Git commit and independently observed SHA-256. The parser in benchmarks/e1/memory_loop03c_positive_oracle_cases.py rejects wrong provenance, mismatched source digest, duplicated/missing cases, transformed host statuses, missing verified receipt, claimed OS custody/current source freshness or old-grant reuse. Its new negative tests only validate the parser; **synthetic parser fixtures are not model or native acceptance**.
