## Work implemented

Its 03A gate labels are **test inputs**, not a real OS or current-goal witness. No positive independently verified procedure, belief, source revision, or actual native tool effect is claimed.

The new `benchmarks/e1/memory_loop03c_real_qwen_comprehension.py` requires this actual native corpus schema, with original current-human identifiers, non-authorizing state, no source freshness claim and no reused grant. It runs the same checksum-pinned real Qwen3-0.6B GGUF using the same seed and inference policy in two arms: (A) original source evidence plus goal/recovery labels without the host decision; (B) the full host-classified 03B capsule. Strict model-response JSON validation rejects duplicate keys, extra tool requests, malformed fields and fake completion. Scores distinguish **model-format/interface**, **Knowledge/source status**, **Authority/unsafe action**, **Feedback/OS or freshness overclaims**, and **source-only context insufficiency**. Preserved raw response SHA, latency and optional token counters allow audit. No model output is generated by fixtures or a mock. Missing actual engine/GGUF fails rather than producing a green result.

The existing manual `lu-memory-loop03b-native.yml` adds genuine Rust corpus export, Python policy regressions and source validation in its Windows/Linux matrix. Optional `run_real_qwen=true` runs pinned llama.cpp + actual checksum-verified Qwen3-0.6B on Ubuntu **only at the end of the task group**. Workflow checks are source-proposed, not executed.

## MEMORY-LOOP-03C-G4 — real test-only Git oracle / positive memory corpus (source candidate)

It then constructs the original human AnsfStore source and ContinuityStore checkpoint, promotes a version-matched verified procedure and a source-linked Claim, and feeds current authenticated human selections through the **actual 03B model-facing host reader**. Six source cases are independently asserted in native Rust:

- Historical observed Git procedure and belief: HISTORICAL_SOURCE_ORACLE_VERIFIED_* at observation only, no current source check or inherited grant.
- Pending goal clarification dominates a historically verified procedure; human review required.
- Version 2.0 cannot recover version 1.0 tool procedures.
- A later original human correction invalidates the historical procedure.
- An original human retraction marks the independently observed Git belief retracted, not current.

A separate memory03c-positive-git-corpus.json can be exported through LU_MEMORY_LOOP03C_POSITIVE_FIXTURE_PATH. Its schema **explicitly labels the witness as test-only direct Git OS commands**, not a production reviewed application worker; it records the original 40-character Git commit and independently observed SHA-256. The parser in benchmarks/e1/memory_loop03c_positive_oracle_cases.py rejects wrong provenance, mismatched source digest, duplicated/missing cases, transformed host statuses, missing verified receipt, claimed OS custody/current source freshness or old-grant reuse. Its new negative tests only validate the parser; **synthetic parser fixtures are not model or native acceptance**.

## MEMORY-LOOP-03C-G5 — reviewed Git/FFprobe worker → ANSF historical memory → changed-source CCM and restart

**Submitted source; native Windows/Linux and genuine-model acceptance OPEN.** New lu-desktop/src-tauri/src/memory_loop03c_reviewed_worker_tests.rs runs within the original ChatStore's profile-owned ANSF/SQLite test module and consumes Lu Core's existing ReviewedApplicationTurnSession. The host explicitly selects real installed Git and FFprobe executables and SHA-pins each image; the model-visible schemas have no executable, argv or file-path arguments. On an **original authenticated human turn with explicit ReadWorkspace and ExecuteCode capabilities**, Lu's native app broker supervises real OS Git HEAD and WAV FFprobe child processes, durably journals outer and inner effects and independently checks original Git/PCM sources using the existing direct host-owned source oracles. The test asserts both inner receipt digests with EffectJournal::independent_verified_receipt before source-linked original M4 procedure and belief promotion. **Scripted model requests drive only the native tool path**; the test does not pretend they are generated by a loaded GGUF.

The integration covers these distinct states: (1) historically verified Git procedure, FFprobe procedure and Git belief; (2) real Git revision committed **after** the old reviewed worker and reported as **historical only**, not current; (3) no automatic reuse of the revoked grant or assistant-generated user event; (4) a second **independently authenticated human turn with a new task/grant** obtains a different Git HEAD through Lu's same protected broker and independent source oracle; (5) a new actual-original ContinuityStore checkpoint records changed source IDs, blocked next action and CCM needsReview, never auto-resumes; (6) a subsequent original human correction invalidates the old procedure and retracts the historical Git belief; (7) reopening persisted ANSF + journal + continuity retains the correction, earlier APPLIED receipts and source distinctions; (8) an additional **journal-only** interrupted intent becomes UNCERTAIN via the existing exclusive-host recovery API, never automatically replays. That journal-only intent did **not** launch an OS child and is not an escaped-descendant cleanup test.

A new optional --reviewed-fixture feeds these original host capsules into the 03C pinned small-GGUF **source-only versus host-classified** benchmark beside G3/G4 fixtures. benchmarks/e1/memory_loop03c_reviewed_worker_cases.py checks eight exact memory/CCM/recovery case names, old/new Git HEAD differences, matching original human turns, independently verified historical receipts, source scope, human review, explicit NOT_RECHECKED, no old grants, and no OS custody claims. Ten adversarial Python tests reject forged worker provenance, changes without a different observed HEAD, reintroduced permissions, missing independent receipts, missing corrections and false CCM. Parsing JSON is not cryptographic proof that a native worker ran; CI must execute the native Rust test at the same exact head and preserve logs.

**CI rule:** the preexisting lu-memory-loop03b-native.yml remains manually dispatched; one Windows/Linux matrix now installs/locates real Git+FFprobe, runs the genuinely reviewed native worker and adversarial contracts, then optionally builds and runs SHA-pinned Qwen3-0.6B once at the task-group boundary.
