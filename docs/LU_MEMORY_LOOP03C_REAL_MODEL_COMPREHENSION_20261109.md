## MEMORY-LOOP-03D — host-owned reviewed-worker journal index in installed Send (source candidate)

The actual installed reviewed-app command already performs fresh native OS user confirmation, registers precisely authorized Git/FFprobe operations, launches supervised workers, independently verifies facts and records immutable effects in a **per-original-human-turn** SQLite journal. Ordinary GGUF Send previously read the separate general DesktopState effects journal and could not see those historical receipts.

This task group introduces reviewed_memory_evidence.rs, a profile-owned SQLite **locator, not a shadow effect journal**, and wires it to both sides:
- The actual reviewed-app command records a bounded, independently VERIFIED Git HEAD or WAV/MP4 duration fact **only after** its native ReviewedApplicationTurnSession has finished. It confirms the worker's original per-turn effect, original authenticated ANSF human source entry, SHA-256 of raw receipt, source-specific independent oracle and current checkpoint. It does NOT accept model-selected executable paths or append APPLIED events to the general journal.
- It creates a source-linked immutable continuity checkpoint, a non-executable M4 version-pinned historical procedure, and a historical verified claim for fixed reserved keys project lu task review_git_head (Git subject git predicate head) or project lu task review_media_facts (media subject media predicate duration_ms). All records carry original source IDs; any later different fact is **blocked for human review** rather than automatically overwriting belief or executing another step.
- Ordinary authenticated Send uses the exact current-human M4 selector to look up an earlier original turn **within the same chat**, derive the known fixed reviewed-effect SQLite basename from that turn, reject symlinks/unbounded files, and recheck the same original effect/tool/receipt SHA-256 and independent source-oracle method. Missing, altered, unsupported or corrupt entries **fail closed**; no fallback to the generic journal after a recorded lookup fails, no old grant is reused, and the model sees NOT_RECHECKED for current source freshness.
- An index entry is idempotent and bound to its exact (chat, original turn, source entry, checkpoint, effect) identity; different bindings are rejected. The positive small-GGUF memory read remains **historical evidence only**, never fresh OS custody, current source state or a user permission.

Explicit example selectors are:
- Recall procedure project lu task review_git_head tool lu.reviewed.git.head tool-version 1.0 application-version 0.1
- Recall belief project lu task review_git_head subject git predicate head version 0.1
- Resume project lu task review_git_head (CCM requires original human review if observed sources differ)

**Acceptance contract:** dedicated Rust unit cases exercise real ANSF/Continuity/SQLite/EffectJournal source and locator boundaries with synthetic worker receipts, including reopen, repeated completion, wrong chat, changed source/CCM, missing receipt/oracle and altered index. They do NOT prove OS worker execution. The separate 03C-G5 **ignored real native Git/FFprobe OS worker test** now calls the exact installed 03D index writer on both fresh human turns and checks that the original journal is found after restart. Both run in the single existing manually dispatched Windows/Linux task-group workflow; no small-commit CI fanout. Actual native compilation, realistic OS run, installed normal-GGUF conversation, real pinned Qwen comparison and cross-process crash ownership are still **OPEN** until independent logs/artifacts pass.
