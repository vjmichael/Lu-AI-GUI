**Status:** source-only, default-OFF, Windows debug builds only. No genuine physical

## Native desktop path

The new Tauri **native OS menu**, never invoke_handler or a model tool, has
three actions: Prepare, Approve, Cancel. Prepare requires exactly one available
active OS-picker-registered project, newest original durable Completed protected
Cargo build, sealed binary/symbols receipts, clean Git HEAD and a new copy and
SHA-256 of the original project source and Cargo manifest. A private Supervisor
writes its original Prepared journal receipt and a non-authoritative admin-review
manifest. No execution, approval or privilege is created.

An independent administrator must recheck all source/build/original host evidence,
privately pin exact Journal/Job ID/full plan SHA/host exe SHA and user SID,
the fixed harmless worker, restricted SCM principal and ProgramData service.json,
read-only service access to original journal and live WFP/Job protections.
The desktop never edits SCM config, bypasses ACLs or creates a privileged service.

Approve obtains only the trusted Tauri-owned main Win32 HWND and demands a
compiled-in exact service SHA and matching image. It reobserves the full original
source/manifest/HEAD/toolchain and sealed build again. The existing C3 native
MessageBoxW requires visible, enabled, same-process, foreground, top-level HWND
and a real NO-default Yes click, then rechecks the complete plan. Only then
can C2's unchanged authenticated SCM peer, suspended native Job, fixed benign
probe, six original fsynced receipts and separate one-use service receipt run.
There is no LLDB, arbitrary PID/command, debuggee or fallback path.
The host also acquires the original FIN-01 global native-worker custody marker
before preparing any C4 job. It independently replays and denies busy
build/debug/LSP journals, checks the original marker during the approval
dialog and releases only once the C4 and sibling original jobs are terminal.
An uncertain death/restart retains the marker for separate kernel recovery.

Cancel only terminates a still-Prepared original job. Uncertain admission remains
quarantined, not replayable.

## Gates still open

C2 original Windows six-receipt and Win/Linux grant tests; independent W2-A
restricted SCM and W2-B Job/WFP. Genuine physical installed Windows menu,

cancellation, service loss, restart/replay and receipt hashes remain unverified.
CI simulated approval is not a real user action. No merge/install/release authority.

The accepted C2 service pins a *single* administrator-selected Job+plan at startup.
This two-stage procedure preserves that design rather than silently introducing
a generic privileged dynamic-command broker. An independently reviewed and
accepted provisioning protocol is needed for automatic per-job enrollment.
