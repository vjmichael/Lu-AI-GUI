## What is implemented and its security boundary

`IdeWorkspaceRegistry::inspect_multi_project_workflow` accepts **only catalog IDs**, not paths. It requires each project to be open and available. `inspect_git_worktree` uses existing read-only libgit2 and rejects dirty/truncated/unverified HEAD; `inspect_project_evidence` uses the existing bounded `cap_std` inventory. Unknown, unhashed, over-limit or truncated files block review. This design **does not** claim Git HEAD protects ignored files: only discovered and independently hashed artifact bytes are included.

`verify_multi_project_workflow` always re-inspects native state and rejects SHA drift. `export_workflow_manifest` and `export_workflow_bundle` only take a **native OS-selected destination**, deny symlink/reparse destination roots, deny writing into registered project roots, and refuse overwriting existing exports. ZIP entries contain `projects/<registered-id>/<verified-relative-path>` with no arbitrary traversal. The ZIP includes a machine-readable `workflow-manifest.json` with `readyForRelease=false` and records observed metadata. The bundle's portable ZIP, although containing byte data, does **not** execute code, stage/commit Git, sign an installer or create OS-worker authority.

The WebView can invoke only named preflight, fresh verification and native export operations. The native host never accepts arbitrary executable names, commands, selected file paths, package scripts, or Git operations through these WO9 requests. Users must explicitly choose projects, review native evidence, reverify, and select an OS export folder. A matching review fingerprint never constitutes approval to ship.

## WO9-D — Reviewed one-file local Git writes implemented

The native `ide/host/src/reviewed_git.rs` module implements three explicitly separated actions: read-only preview of one already **tracked regular file** inside the exact picker-registered Git root; stage only that file's SHA-rechecked buffered bytes with `git2::Index::add_frombuffer`; and commit exactly one staged file, conditional on the old branch ref still matching the preview HEAD. Index-fingerprint drift, external file edits, unrelated staged changes, rename/path traversal, Git symlinks, gitlink/submodules, detached HEAD, oversized source, stale commit and reused review are denied. The host does not spawn Git CLI, hooks, merge, network fetch or push.

The installed Source Control UI provides file-relative input, digest/HEAD review, separate **real operating-system confirmation dialogs** for staging and committing, human-entered local commit identity/message and exact commit result. Native Rust fixtures create real libgit2 repositories and exercise stage, conditional commit, stale buffer refusal and guardrails. A WO9-F installed Windows UIA scenario also installs the desktop, stages/commits a tracked file with explicit OS dialogs, verifies that exactly that file changed, and writes a malicious pre-commit hook to prove the IDE did not execute Git hooks.

**Current status:** implementation committed, native exact-head compilation/test and installed-app evidence **not yet granted**. Git write functions are deliberately limited to one tracked regular file per approval; bulk stage, unstage, branch switching and push remain **unsupported** rather than silently authorized.

## WO9-E — Durable multi-project DAG and existing supervised workers

`ide/host/src/workflow_orchestrator.rs` writes a bounded (`<=16` workflows, `<=12` ordered steps each) fsynced app-profile journal. Each step selects an explicitly picked project and one of three fixed offline Cargo recipes; dependencies can point only to **earlier** steps, preventing cycles by construction. A graph records *pending* work only—no execution privilege, grants, or background launch. Manual `ide_workflow_run_step` checks the exact whole-portfolio fingerprint and completed dependencies, journals *running* **before** any dispatch, and passes the step to the **existing WO6 protected NativeBuildRuntime**, which independently requires its signed/pinned resource checks, one-use native confirmation, and OS containment. On return, only the trusted native result updates terminal state. A step is *passed* only after a completed exit-zero verified output digest; failed/denied jobs remain failed and cannot unblock descendants. On host restart, *running* records become fsynced *interrupted*, never replayed. A task without a trustworthy terminal OS receipt is quarantined; pending cancellation is durable, while executing-job cancellation belongs to WO6's actual supervisor.

The Packages & Workflows GUI now builds arbitrary earlier-step-only dependencies, persists them, shows exact durable terminal receipts, offers individually approved eligible steps, and never automatically retries after a crash. Real native Rust tests cover cycles, duplicate deps, persistent restart quarantine, native-source planner gating, successful and failed dependency transitions, and OS admission denials.

**Current status:** code implemented; Windows/Linux native exact-head CI verification is required; **signed installed protected run cannot yet be accepted** because WO6/WO7 installed pins, worker and code-signing prerequisites are not approved.
